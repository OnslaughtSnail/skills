# 语言适配

遵守当前语言、项目版本、已有 API 和真实运行环境。

## 共同裁决

| 遇到的建议 | 用于当前工程的判据 |
| --- | --- |
| 函数应短 | 抽取是否减少读者必须理解的信息；不能只按行数拆分 |
| 参数应少 | 是否存在自然概念或误传风险；不能换成共享可变状态 |
| 避免布尔参数 | 区分模式切换与真实布尔数据，保留必要兼容性 |
| 避免重复 | 合并同一知识，避免把独立变化的政策绑在一起 |
| 避免 switch | 检查重复分派和变化方向；清晰的封闭状态分支可以保留 |
| 避免空值 | 明确缺失、空结果与失败，维护对外表示 |
| 使用接口 | 真实边界需要什么能力；无需让每个实现配套一个接口 |
| 一测试一概念 | 同一概念可以有多个断言；不按断言数拆测试 |
| 尽量少注释 | 保留无法从代码可靠推断的理由、算法和契约 |
| 测试驱动 | 新行为和修复尽早建立预期；重构保护既有行为，机械改动复用检查 |

## Go

- 保留明确的 error 返回和调用方检查；不为模拟异常，把普通业务失败改成跨 API 的 panic。
- 保留调用方需要识别的错误身份；添加上下文时按项目约定包装。不要把所有错误变成格式化字符串或 nil。
- 接口优先从真实使用方的需求产生，保持窄。不要为了未来实现或 mock 给每个结构体创建全量接口。
- 使用 gofmt 和项目约定。i、r、ctx 等短名称在合适作用域可以清楚；命名长度不单独构成问题。
- 变更 nil slice 前检查编码契约；标准 JSON 编码下 nil 与空 slice 的外部表示可能不同。
- 保持资源所有权、defer 清理和取消传递清楚。启动 goroutine 的位置必须能说明其退出条件。
- 从当前模块和工具链确认语言版本、库 API 和运行命令。

## Python

- 判断 None 时保留明确的身份比较；不要将合法的 0、False、空串或空列表误判成缺失。
- try 范围只覆盖打算处理的失败；不要用宽泛 except 吞掉附近代码的编程错误。
- 根据已有约定用 with 或 finally 管理资源，保持异常原因及清理语义。
- 简单函数、数据类或模块足够时，不移植 Java 式接口、继承和工厂层。
- 保留关键字参数、动态注册和公开名称的兼容性；不能仅凭静态搜索认定无调用。

## TypeScript／JavaScript

- 对有限状态或消息集合，可以用判别联合与 switch 表达；类型检查可用 never 核对分支穷尽。
- 保留 null、undefined 与合法假值的区别。不要用 truthiness 或非空断言掩盖真实契约。
- 类型声明不能证明外部输入有效；在现有系统边界处理验证，不机械地在每层重复校验。
- 调整 Promise、事件监听和异步任务时，检查拒绝、取消、监听移除及完成顺序。
- 不为了“面向对象”把清楚的数据变换改成多层类结构。

## Java 及其他语言

- 错误码、checked exception、导入、继承和框架的取舍遵循当前项目约定。
- 保留序列化标识、公开签名和错误契约；不能为统一风格删除兼容机制。
- 资源管理与并发原语使用当前项目支持的惯用方式，不能照抄演示代码的生命周期缺口。
- 其他语言同理：把原则映射到其类型、错误、所有权与模块机制；不能从 Java 术语推导必须采用相同结构。
