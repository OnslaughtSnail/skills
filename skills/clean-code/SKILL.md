# 整洁代码：执行协议

在完成用户目标的同时，降低下一位维护者阅读、修改和验证代码的成本。
把正确性、已确认的行为契约和当前任务范围放在风格偏好之前。

## 1. 确定本次工作模式

- **设计／方案**：从需求、约束和已有系统出发，明确职责、依赖方向、状态所有权、关键契约与验证方式；比较有实际差异的方案和取舍，不把方案请求当作实施授权。
- **审查**：只读分析，追踪问题、核验证据并报告；未经任务授权，不修改、提交或发布。
- **实现／修复**：完成已明确的需求及其必要的局部整理；用需求和现有调用约定判断预期行为。
- **重构**：保留可观察行为，分步改善结构；新发现的缺陷与结构调整分别处理，不能悄悄修改契约。
- 从用户请求判定模式。仅在剩余歧义会实质改变结果、且无法通过代码、测试或文档消除时询问。

## 2. 先建立最小必要上下文

1. 读取项目约定、相关变更、实现入口、直接调用者和已有测试。优先用精确搜索追踪符号与配置。
2. 确认输入输出、失败语义、默认值、副作用、状态所有者及兼容面。涉及 I/O 或并发时补齐资源与生命周期。
3. 查清未知行为；第三方 API 不确定时查当前文档或做最小实验。不能凭函数名猜契约。
4. 找到项目已有的构建、格式化和测试入口。只读取影响当前判断的范围，证据需要时再扩展。

## 3. 用收益决定是否改动

每个结构性改动都要能够说明：

> 当前什么事实造成了理解、修改或验证困难；这个最小调整怎样减少该困难；哪些行为必须保持。

先考虑准确命名、明确条件、收拢相关逻辑、删除已证实的冗余，再考虑抽取或拆模块。
新抽象必须隐藏真实细节、维护不变量、隔离实际变化，或统一同一项业务知识。
若调用者仍须读完所有被调函数才能理解状态和顺序，重新划界或内联。
能够指出收益即可，不为每个小编辑生成设计文档。

## 4. 遵守这些边界

- **不以指标定罪。** 行数、参数数、分支、重复、注释量和类数量是调查线索；单独不足以证明缺陷。
- **不转移复杂度。** 不为减少参数而把局部数据改成共享字段；不靠转发层、全局工厂或万能配置藏起依赖。
- **不预建未来。** 当前没有真实需求时，不引入扩展框架、每类型一个接口、通用引擎或第二套状态权威。
- **不改变语义以求整齐。** 保留序列化、公开名称、空值、错误类别、顺序、原子性及必要性能约束。
- **不把未知伪装成成功。** 不擅加默认值、重试、吞错、空结果或 fallback；失败必须仍能被调用方正确处理。
- **不越过兼容边界删除。** 仓库内搜索不到引用，不足以删除公开 API、注册入口、反射成员或外部协议。
- **不机械移植语言习惯。** 用所在语言和项目的惯用机制表达原则；例如 Go 的业务错误通常返回 error。
- **不掩盖失败。** 不通过放宽断言、删除失败测试、关闭检查或无限重试使结果变绿。

已有不合理行为需要修复时，先用需求或契约确认其错误；修复必须在当前授权范围内，并有对应验证。

## 5. 小步执行并核对效果

设计／方案任务通过需求场景、失败路径和边界检查验证可行性；尚未实现的方案不得声称已通过运行验证。以下步骤用于实现、修复和重构。

1. 先确认当前实现与验证基线；对有行为风险且缺乏保护的路径，补充最小有效验证。
2. 一次处理一个可解释的变化。结构调整与行为修复保持可区分，不叠加多个尚未验证的假设。
3. 每个有效步骤后运行与其风险匹配的检查。失败先定位；必要时撤回自己刚做的步骤，不覆盖用户修改。
4. 新增或修复行为时检查正常、失败和相关边界；外部契约变化检查真实边界或集成路径。
5. 检查最终差异，删除已完成迁移的旧分支、临时双写、无意义转发及过时注释；保留仍有契约用途的兼容层。
6. 验收时从调用者角度读一遍：依赖更明确了吗？关键状态更集中了吗？必须同时理解的位置更少了吗？

验证必须能回答具体风险。复用已有测试；不为低风险机械修改或每个私有 helper 增加镜像测试。
不得把单测通过等同于协议兼容，把覆盖率等同于正确性，或把未复现竞态等同于并发安全。

## 7. 交付并收敛

**设计／方案输出**：说明推荐方案、职责与依赖边界、关键契约、主要取舍及验证计划；按任务规模提供必要细节，区分已确认事实和待验证假设。

**审查输出**：按影响排序，每项给出位置、触发条件／可复核事实、实际影响及最小修正方向。
区分已证实缺陷、明确的维护成本和待证实疑点；纯偏好不升级为阻塞问题。
没有足够证据支持的问题时，明确说明未发现确证问题，不为凑数量制造发现。

**实现／重构输出**：说明完成了什么、为什么、执行了哪些验证及结果；未执行的检查必须说明。
提供必要的剩余风险，不罗列无关的整洁性建议，不声称证明了所有情况正确。

目标已完成、必要验证已闭环且剩余改动只有偏好差异时停止。
保持清晰现状、拒绝无收益的改造，也是一种合格结果。
